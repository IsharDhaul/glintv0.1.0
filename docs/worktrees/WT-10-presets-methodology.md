# WT-10 · presets-methodology

| Wave | Size | Needs merged | Worktree | Branch | Ports |
|---|---|---|---|---|---|
| 3 | S–M | WT-06 (WT-08 to check presets in the UI) | `wt10-presets-methodology` | `worktree-wt10-presets-methodology` | api 8010 / web 3010 |

**Goal.** Twelve presets that return workable lists on real data, plus the methodology and metric dictionary that make every number explainable.

**Owns.** `config/presets/*.json`, `docs/methodology.md`, `web/src/content/` (about and methodology copy), definition *wording* in `config/metrics.yaml`, the generated `docs/metrics.md`, `docs/decisions/WT-10.md`.

**Must not touch.** Formulas, thresholds in `thresholds.yaml` or engine code.

**Steps**

1. **Presets.** Write all 12 from §2.8 with `summary`, `how_to_read`, `source` and `screen`. Run each with `glint screen <id>`.
   - Tune *universe* bounds and thresholds only until each returns roughly 10–100 names (net-nets may be fewer, and say so).
   - Log every threshold change, with before and after counts.
2. **Source lines.** Cite the book or paper (author, title, year). Don't claim returns. Where Glint's version differs from the source (shareholder yield excluding debt paydown; Greenblatt ROC as defined in §2.4), say so in `how_to_read`.
3. **Methodology** (`docs/methodology.md` and the `/about` page):
   - Data sources and tiers
   - Universe rules
   - Period rules (TTM, MRQ, averages)
   - The applicability matrix
   - Null codes in plain English
   - SIC-based sectors (not GICS)
   - Foreign filer limits
   - Survivorship and look-ahead disclaimer
   - "Educational tool. Not investment advice."
4. **Metric dictionary.**
   - Review every live metric's `definition` text for plain English. Each needs one sentence on *what it tells you* and one on *where it misleads*.
   - Add a worked example per metric using a real ticker, generated by `glint metrics <T> --explain <id>` output, never typed by hand.
   - Run `make docs`.
5. **Consistency test.** Every preset metric exists, is live and is P0, and every preset passes validation.

**Acceptance criteria**

- [ ] 12 presets run on the real build, with counts recorded in the decisions file (before and after tuning).
- [ ] Every preset has a source and a how-to-read, with no returns language. A grep test bans "outperform", "beat the market" and "returns of".
- [ ] The methodology page is complete and linked from the footer.
- [ ] Every live metric has plain-English what/where-it-misleads text and a generated example.
