# UI upgrade decisions

One dated line per non-obvious choice made while working through `docs/glint-ui-upgrade.md`.

## Phase 0: recon and trust fixes

- 2026-11-22 · The brief was untracked at the repo root; moved to `docs/glint-ui-upgrade.md` so it's versioned with the work.
- 2026-11-22 · Phase 0 ran on branch `ui/phase-0-trust` in its own worktree, because `main` had uncommitted Up-C work (`config/sectors.yaml`, `engine/glint/universe/*`) that this phase shouldn't touch.
- 2026-11-22 · The mock now filters for real. `web/src/mocks/evaluate.ts` re-implements the engine's rules over the mock companies: universe, percent_rank, sector medians, small-peer nulls, missing policy, sequential funnel, near-miss explanation and ranking. Results, near misses and why-passed all come from one evaluation, so they can't disagree. The old seeded sampler (`rng.ts`) is deleted.
- 2026-11-22 · The mock's screen settings (`float_tolerance`, `small_peer_group_min`) ship in `web/mocks/profiles.json` from `config/thresholds.yaml` (principle 8). `MAX_NEAR_MISSES = 25` is repeated from the engine's own code constant.
- 2026-11-22 · Mock mode's universe is the 300 exported companies. `web/mocks/meta.json` universe counts now describe those 300, not the 6,000-row build, so the header count matches the first sieve stage.
- 2026-11-22 · `glint fixtures synthetic` now exports each company's header, flags and history (`profiles.json`, `history.json`), and the mock serves them as they are. The mock invents no flag, filing date or history point.
- 2026-11-22 · Synthetic values are rounded to 6 dp once, at generation, so the build and the mocks hold identical numbers. A history series' newest point is that rounded headline value. Flag evidence carries the exact metric value, not a re-rounded copy.
- 2026-11-22 · `?mock=empty` appends a filter nothing passes (labelled "Empty-results scenario" in the sieve), so the empty state still sits on an honest funnel.
- 2026-11-22 · Mock sources are derived from the header's 10-K and 10-Q dates, with fake accession numbers that link nowhere, so "days since filing", the filing dates and the sources list agree.
- 2026-11-22 · Screen check heading: "Passes all N" or "Passes N of M", plus "Fails <metric names>" when any fail; "Screen check" when the company is outside the screen's universe. With no screen there's nothing to check, so the section is left out. Verdicts roll leaf outcomes up to top-level filters (`lib/screen/check.ts`), because an OR group can pass while a child fails.
- 2026-11-22 · Near-miss distance is displayed in the metric's own unit, computed from value and threshold ("7.5 pp short", "0.4x over", "$120M below the range", "3.0 pts short"). The engine's relative `distance` still orders the list, because pp can't be compared with $. The engine has no `abs()` bug, since distance is only computed for rows that fail. The bad near misses in the review came from the mock sampling passing rows.
- 2026-11-22 · Removed the P0/P1 and "planned" badges from the dictionary and metric picker. `/api/metrics` returns live metrics only, so "planned" never described anything a real-build user could see.
- 2026-11-22 · Registry prose is translated for display by `plainText()` (`lib/labels.ts`): reason codes become words, and § references and config paths are dropped. `config/metrics.yaml`, the API and `docs/metrics.md` keep the precise wording. Rewriting the source text belongs to Phase 4 item 11.
- 2026-11-22 · Null-value tooltips no longer print the reason code (`DERIVED_INPUT` etc.); the plain label and the API's message remain.
- 2026-11-22 · Engine invariants (`engine/tests/api/test_invariants.py`) run on a synthetic build. A real build is checked only when `GLINT_INVARIANTS_DATA_DIR` is set, so tests still never read real data dirs by default.
- 2026-11-22 · `devIndicators: false` hides the Next.js dev badge. The dev overlay's "Insight" pill (a framework security notice) still shows in `next dev` only, never in production builds.
- 2026-11-22 · A worktree needs its own `npm ci`: Turbopack refuses a `node_modules` symlinked from outside the project root.

## Phase 2: handoff spec

- 2026-11-22 · The collapsed histograms are a display bug: the API already bins p1–p99 with the tails in the two end bins, but `Histogram.tsx` draws bins on a linear min–max axis, so a −17,919% minimum stretches one bin across the chart. The spec draws bins at equal widths and labels the end bins as under/overflow. No computation changes.
- 2026-11-22 · Sieve trays are scaled linearly to the universe (not √), with kept / failed / no-data segments, so every tray is read against the same frame.
- 2026-11-22 · Near misses group by failed filter and sort by gap in the metric's units within a group; across groups they keep the engine's relative order, since pp and $ can't be ranked together.
- 2026-11-22 · Non-interactive pills (flag count, coverage, tier, kind) become plain text; Chip is only for removable or toggleable things.
- 2026-11-22 · The gold `.glint-new` shimmer is replaced by a 1.5s purple left bar on rows that entered because of the user's edit (static under reduced motion).
- 2026-11-22 · Company opened without a screen: no screen check, and the screen-metrics block becomes a fixed "Key metrics" set.
- 2026-11-22 · `no-raw-style.test.ts` will enforce tokens-only styling (no hex, rgb, arbitrary sizes, uppercase, tracking, or mono outside the allow-list), alongside `no-stray-formatting.test.ts`.

## Phase 3: interaction architecture

- 2026-11-22 · Measured, not guessed: server `run_screen` on the real build takes 37–233 ms median (p90 up to 566 ms) per preset before HTTP, so live dragging can't round-trip. A client columnar evaluation of the same 7,992 × 70 data takes 3.1 ms median / 4.9 ms p95 at 4× CPU throttle. Details in `docs/interaction-architecture.md`.
- 2026-11-22 · Proposed (awaiting the user's OK): a client-side live preview with the server authoritative on settle, plus a CI parity test against the engine.
- 2026-11-22 · Float64 columns (1.84 MB gzip), not Float32 (1.01 MB): Float32's 6×10⁻⁸ error can flip threshold comparisons relative to the engine.
- 2026-11-22 · No Web Worker yet: compute uses under 10% of the budget. Revisit if the Phase 4 perf test's p95 exceeds 35 ms.
- 2026-11-22 · URL state stays hand-rolled (extend `useScreenUrlState` with `t`, `d`, `c`); selection changes replace history, screen edits push.
- 2026-11-22 · Histograms are binned client-side per universe (p1–p99, explicit underflow/overflow, missing vs n/m), so `/api/distribution` needs no contract change.
