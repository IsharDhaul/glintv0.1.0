# WT-02 decisions

- 2026-10-29: Massive API as found in its docs today: base `https://api.massive.com` (from the REST quickstart examples), auth `Authorization: Bearer <key>` (the docs also allow `?apiKey=`; the header keeps keys out of logged URLs). Grouped daily = `GET /v2/aggs/grouped/locale/us/market/stocks/{YYYY-MM-DD}?adjusted=false` (params `adjusted` default true, `include_otc` default false; response `results[]` of `T o h l c v vw t n otc?`). Splits = `GET /stocks/v1/splits?execution_date.gte=…&limit=5000&sort=execution_date.asc` (paginated by `next_url`; fields `ticker execution_date split_from split_to adjustment_type historical_adjustment_factor id`). Per-ticker history = `GET /v2/aggs/ticker/{T}/range/1/day/{from}/{to}?adjusted=false&sort=asc&limit=50000`.
- 2026-10-29: Store **unadjusted** bars (`adjusted=false`) plus `splits.parquet`, and split-adjust at read time — deviates from the brief's "split-adjusted bars" on purpose: Massive adjusts as of the *fetch* date, so stored adjusted partitions silently go wrong at the next split until a full re-backfill. Raw bars never change, market cap needs the unadjusted close anyway (WT-06), and returns still use adjusted closes.
- 2026-10-29: The PriceProvider protocol adds `name`, `is_fallback` and a `prefetch(days)` hint to the brief's three methods — `is_fallback` drives the "fallback mode" message; `prefetch` lets yfinance download a whole backfill window in batches instead of one download per date (Massive ignores it).
- 2026-10-29: "Never today" means New York's calendar date: the newest requestable date is yesterday in America/New_York, whatever the local clock says.
- 2026-10-29: `MASSIVE_BASE_URL` (default `https://api.massive.com`) lives in a provider-local `MassiveSettings`, not `core/settings.py` — core settings are a WT-00 contract, and only the price provider reads this value.
- 2026-10-29: "Every call is cached": per-ticker history (30-day TTL; unadjusted past bars don't change) and splits (12 h TTL) go through `core/cache.JsonCache`. Grouped-daily dates are *not* double-cached as JSON (~1 MB each); their cache is the parquet partition plus the holiday record, and ingestion never refetches either.
- 2026-10-29: Massive retry policy: 429 → honour `Retry-After` (default 60 s) by blocking the whole pacing window; 5xx/network → exponential backoff 2, 4, 8, 16 s, 5 attempts; 401/403 → fail at once with a "check MASSIVE_API_KEY and your plan" hint. Weekends return `[]` without spending a call.
- 2026-10-29: yfinance fallback downloads with `auto_adjust=False, actions=True` and always through today, then un-adjusts with the `Stock Splits` column (raw = Yahoo close × product of later split ratios; volume ÷ the same) — Yahoo's `Close` is split-adjusted as of the download date, and Glint stores unadjusted bars. Batches of 200 tickers with 2 s pauses; any exception becomes `SourceError`; a window with no bars at all is an error, never "a holiday".
- 2026-10-29: Provider choice: `GLINT_PRICE_PROVIDER=massive` with a key → Massive; without a key → yfinance flagged `is_fallback` and a `price_provider_fallback` warning; `GLINT_PRICE_PROVIDER=yfinance` → yfinance, not labelled a fallback.
- 2026-10-29: Storage files are written to `<name>.tmp` then renamed, and a date only "exists" when `date=…/part.parquet` does — a kill mid-write leaves a stray `.tmp` that the next run overwrites. Holidays live in `prices/holidays.json` (date, source, recorded_at); reports in `prices/reports/`.
- 2026-10-29: Holiday handling (tightened after review): a weekday with no bars goes into `holidays.json` only when dates **on both sides** of it have bars. An empty date at the newest end (not published yet?) or the oldest end (beyond the plan's history?) stays unconfirmed and is asked again next run. A 200 whose `status` isn't OK/DELAYED is an error, not an empty day. Weekend `--date`s are skipped, never recorded. No exchange calendar is hard-coded: the provider's empty answer is the evidence. Known limit: a one-off empty answer for a real trading day *between* two good days would be stamped. The fix is deleting that line from `holidays.json`; there's no `--recheck-holidays` yet.
- 2026-10-29: Backfill stop rule: give up walking back after 5 consecutive empty weekdays (the longest US closure since 2001 was 4) or after `sessions × 2 + 30` weekdays, and report `history_exhausted`. Without it, a plan's history limit answered with 200/empty would loop forever at 12 s a call.
- 2026-10-29: Each partition records who wrote it in `date=…/source.json` (written after the parquet; missing = unknown). Massive skips only dates *Massive* wrote, so dates a yfinance fallback filled for a handful of tickers are fetched again once a key is set. yfinance accepts any partition. Files are fsynced before the rename.
- 2026-10-29: No fills: a missing open/high/low/volume/vwap stays null in storage (providers used to turn a missing volume into 0, and yfinance used the close for a missing open/high/low). `avg_dollar_volume_3m` is null with `MISSING_INPUT` if any volume in its 63-session window is missing. A real zero volume stays a zero.
- 2026-10-29: Stale prices: `price_stats.as_of` is each ticker's own last bar. Deciding staleness (`STALE_DATA` when that's older than the build's price date) is left to WT-06, which owns `metric_notes`; this module reports the date honestly and doesn't judge it.
- 2026-10-29: yfinance prefetches with 21 days of slack and answers `splits()` from the loaded window, so a backfill walking past holidays, and the post-run split merge, reuse one download instead of re-downloading the universe.
- 2026-10-29: Backfill counts **sessions**, not weekdays: `--backfill N` keeps walking back past holidays until N dates with bars are on disk. ETA = dates still to fetch × 60 / `MASSIVE_CALLS_PER_MIN`, logged in the plan line and after every saved date.
- 2026-10-29: Canonical symbol rules (in `symbols.py`, from real files): one dotted spelling per listing type. Class `BRK.B` (Massive `BRK.B`, SEC/Yahoo `BRK-B`); warrant `X.WS` (SEC `-WT`); unit `X.U` (SEC `-UN`); right `X.R` (SEC `-RI`, Massive `Xr`); preferred `X.P`/`X.PD` (SEC `-PD`, Massive `XpD`). The first version left Massive's lower-case markers alone, so 375 SEC preferreds looked unpriced. Partitions written before the fix were migrated once, under the lock (11,288 symbols renamed, no collisions). WT-01 should adopt the same suffix rules for non-common lines.
- 2026-10-29: Coverage is measured on **common-stock listings** only; warrants, units, rights, preferreds and when-issued lines are counted separately. Nasdaq 5-letter symbols ending W/U/R/P/Z also count as non-common. It's reported on the latest date *and* within the last 5 sessions, because grouped daily lists only tickers that **traded** that day. Thin names skip days (AKA traded 27 of 30 sessions).
- 2026-10-29: **Real coverage, 2026-10-28** (universe = SEC `company_tickers_exchange.json` of 2026-10-29): **6,144 / 6,336 common NYSE+Nasdaq listings priced that day = 97.0%**; 6,292 / 6,336 = **99.3% within 5 sessions** (NYSE 2,751/2,766, Nasdaq 3,541/3,573). The 44 with no recent bar are mostly SPACs not yet trading, plus ATKR, BZH and ACVA, which stopped printing mid-October (likely delisted/acquired; SEC still lists them), SVA (halted), and a few new small caps. Full list in `prices/reports/coverage-2026-10-28.json`. The first, naive measure was 85.5%, because the denominator included 1,290 non-common lines and preferred spellings didn't match.
- 2026-10-29: "Close N sessions ago" needs N + 1 rows (the metric text's "fewer than 21 sessions" reads as 21 *prior* sessions plus today). Volatility uses 252 log returns, so 253 closes, with the sample stdev (ddof=1). The 52-week high needs 252 closes, inclusive of today, from adjusted closes. Sessions are the ticker's own trading days, and each ticker's `as_of` is its own last bar, so a halted or delisted ticker shows its real price date rather than a borrowed one.
- 2026-10-29: `price_stats.close` is the **unadjusted** last close (what traded on `as_of`; WT-06 multiplies it by shares). Returns, the high and volatility use split-adjusted closes. Dollar volume = raw close × raw volume, which doesn't change across a split. Splits dated after `as_of` (announced, not yet effective) are ignored.
- 2026-10-29: `split_between(ticker, d1, d2)` = product of ratios for splits effective in **(d1, d2]**. A split effective on d1 is already in a share count taken at the end of d1. Returns `None` when there is no split, so WT-06 can tell "no split" from "ratio 1". A vectorised `SplitIndex` serves many lookups.
- 2026-10-29: Session windows (21/63/126/252/63) are module defaults in a `Windows` dataclass, not `config/thresholds.yaml`. They are the metric *definitions* written in `config/metrics.yaml` (owned by WT-06), not tunable thresholds, and tests shrink them to hand-computable sizes.
- 2026-10-29: Removed WT-02's two rows (`ingest prices`, `price`) from `STUBS` in `engine/tests/test_cli.py` (a WT-00 file). Implementing the commands makes those stub assertions false. WT-03 did the same for its own row, so each worktree deleting only its own line merges cleanly.
- 2026-10-29: `glint price` reads only what's on disk (no provider, no network) and labels itself "tier 2 market data". Null stats show the `NOTE_DISPLAY` glyph plus the reason. It accepts SEC-style `BRK-B` as well as `BRK.B`. `glint ingest prices` with no options catches up from the newest date on disk. After every run it writes `prices/reports/coverage-<date>.json`, as long as the SEC tickers file exists.
- 2026-10-29: Plan limits as found with a real free ("Stocks Basic") key: grouped daily for 2026-10-28 returned 12,613 unadjusted rows (`status: OK`, plus an undocumented `count` field). 2024-10-28 returned **403 NOT_AUTHORIZED "Attempted to request data past historical entitlements"**, so history is about 2 years. That 403 becomes `HistoryLimitError`, and the backfill stops there and reports `history_exhausted` instead of failing. Massive writes Berkshire as `BRK.A`/`BRK.B`, confirming dot = canonical.

- 2026-10-29: Splits are refreshed only when a run fetched new bars. A run with nothing to do makes zero provider calls; before this, a yfinance run on an up-to-date store re-downloaded the universe's history just to answer `splits()`.
- 2026-10-29: **The fallback no longer goes through the yfinance library.** Diagnosis (same URL, same machine): plain TLS (httpx) → 200; curl_cffi without impersonation → 200; curl_cffi impersonating chrome/safari/firefox → TLS "connection reset by peer". yfinance 1.7.0 (curl_cffi 0.17.0) always impersonates, even when handed a plain session, and it failed identically from the user's own terminal. So it's the library's transport, not the network. `yahoo_chart.chart_download` calls the same chart endpoint (`/v8/finance/chart/{sym}?period1&period2&interval=1d&events=split`) over httpx, with a 0.25 s pause per symbol. It returns the yfinance-shaped frame, so the un-adjust logic didn't change. It reads only `timestamp`, `quote` and split events; never `meta`'s vendor fields such as `fiftyTwoWeekHigh`. The provider keeps the name `yfinance` (the settings value). The `yfinance` dependency in `pyproject.toml` (a WT-00 file) is left in place and is now unused by WT-02. `pandas`, which `yahoo_chart.py` uses, is installed only through yfinance, so removing yfinance later must add `pandas` as a direct dependency in the same change.
- 2026-10-29: Fallback verified live: 6/6 tickers for 2026-10-28 match Massive's closes to the cent (AAPL 343.83, MSFT 531.01, NVDA 215.38, BRK.B 540.34, GOOGL 324.89, KO 91.73). NVDA un-adjusts to $1,208.88 on 2024-06-07, the real pre-split close of the 10-for-1.
- 2026-10-29: Why a `--date 2026-10-28` run fetches from 2026-10-07: `prefetch` adds 21 days of slack, so a backfill that walks past holidays stays inside one download. With the chart endpoint, a range costs one request per symbol whatever its length, so the slack adds bytes, not calls. The "no bars" error now names the window and why it's wider than asked.

- 2026-10-29: **Price history follows the company across ticker changes** (fix PR after WT-02 merged, requested by the user ahead of Texas Capital `TCBI` → `TXCP` on 2026-11-09, CIK 1077428). New `config/ticker_changes.yaml` (CIK, old, new, effective date, evidence) and `glint.ingest.prices.ticker_changes`. Files on disk keep the symbol that traded each day. `PriceStore.read_bars` and `load_splits` relabel the old symbol's bars and splits dated before `effective` to the new symbol, but only once the change is effective in the data (newest date on disk ≥ `effective`). Until then `TCBI` reads as before. New-symbol rows dated before `effective` are dropped (another security that used the symbol); old-symbol rows from `effective` on are left alone (symbol reuse). `glint price TCBI` after the change says it became `TXCP` and shows the joined series. Changes are entered by hand with evidence. No automatic detection: SEC's ticker file keeps only today's mapping, and per-ticker provider calls are out of budget. `TCBI-PB` isn't listed because no rename has been confirmed for it.

- 2026-11-03: **Same-day split legs are all kept and netted on read (fix PR from main, hand-off in WT-06.md; user decisions: keep every leg, defer ADR detection):** `merge_splits` deduplicated on ticker + execution date and kept the first row, so a second event on the same day was dropped. Massive returns Tile Shop's odd-lot transaction as two legs on 2025-12-16 (1 → 3,000 forward and 3,000 → 1 reverse); only the forward leg was stored, a phantom 3,000-for-1 that divided every earlier TTSH close by 3,000 and that `split_between` reported. The key is now ticker, date and ratio (log10 of split_to ÷ split_from, 4 decimals, so the same event with provider rounding, CRESY 1.00846 vs 1.008459562, stays one row); `load_splits` nets same-day legs into one row (froms and tos multiplied, types joined with "+"; TTSH: 3,000 / 3,000, "forward_split+reverse_split"). Consumers already multiplied every split in a range, so netting changes only the row count they see. The cached Massive responses (2025-08-20, 2026-09-17; 2,311 rows) hold 8 rows the store lacks: TTSH's reverse leg and 7 second events on OTC tickers (stock dividends beside a split: NWSZF, AFOVF ×3, HUWWF, CTRGF, BSTGF). The store is repaired from that cache under raw.lock after this merges, so no run on the old key collapses the restored legs again. Not changed: ADR ratio changes (AZN 1-for-2 on 2026-02-02, AKTX 1-for-40 on 2026-03-31) come as plain `reverse_split` rows and are real for the ADS price; telling them apart from share splits needs ADS data WT-02 doesn't have (Massive's ADRC ticker type or the filings' ADS ratio), which waits for F20 (FX + ADR ratios). Near-1 rows are mostly typed `stock_dividend` already (AIM 1,000 → 1,001, SCCO ~1% quarterly), real share events; TRI's 1.015682 `reverse_split` is a share consolidation. Diluted-share comparisons are guarded by WT-06's confirmed-split rule (#43); market cap still applies every row.
