- 2026-10-31: `make dev` reads `GLINT_API_PORT` and `PORT` from the shell env, then the root `.env`, then falls back to 8000/3000. That's the engine settings' precedence. It doesn't source `.env`, because the file isn't shell syntax: unquoted values contain spaces, so sourcing it would run them as commands. It passes the web `NEXT_PUBLIC_GLINT_API_URL=http://localhost:<api port>` and `NEXT_PUBLIC_GLINT_MOCK=0` explicitly. Before this, the root `.env` ports reached neither server: Make doesn't read `.env`, and Next only reads `web/.env*`. One Ctrl-C stops both servers. If either one exits (say its port is taken), the other is stopped and `make` exits non-zero. macOS ships bash 3.2, which has no `wait -n`, so a 1 s `kill -0` poll stands in.
- 2026-10-31: `glint smoke` runs in-process: a Starlette TestClient over `create_app()` and the current build. It goes through the same routes, validation and error handlers the UI hits, without starting a server or opening a socket. Every body is parsed with the contract models, so a shape drift fails the check too. Expectations live in `engine/glint/smoke/expectations.yaml`, not in code. Besides the pinned null reasons, every Appendix D company is checked against the registry's §4.5 matrix (every metric n/m for its sector or REIT status must say NOT_APPLICABLE_SECTOR) and against principle 3 (no null without a reason).

## Deferred

- Mock CSV export doesn't match the API: for a ranked screen the API leads with `rank` (§2.10: the visible columns, and `#` is visible), while `web/src/mocks` starts at `ticker`, and the mock e2e (`e2e/export.spec.ts`) pins that. The mock should follow the API. That's a separate web change, because the mock spec changes with it.
- SEC's SIC 7389 ("Services-Business Services, NEC") is a catch-all, and `config/sectors.yaml` maps it to Industrials, so MercadoLibre (MELI) and Nutex Health (NUTX) show as Industrials. That's correct by the rules. A fix belongs in `config/sector_overrides.yaml` (WT-01), case by case.
- Free-text `notes` in the CSV can contain "%" (e.g. "Factor coverage 50% < 70%"). Value cells are fractions, as they should be.

## Bugs for separate PRs (outside WT-09's paths)

- 2026-10-31 · `engine/glint/core/settings.py` (WT-00 core, via §8.6): relative paths and `.env` resolve from the *imported package's* location (`REPO_ROOT = Path(__file__).parents[3]`), not from the checkout you run in. Running from a worktree under a venv that belongs to another checkout (VS Code exports `VIRTUAL_ENV` pointing at main's `engine/.venv`) imports main's code, reads main's `.env`, and makes `GLINT_DB_DIR=./data` write into main's `data/`. Nothing warns. Reported by WT-10. Fix to discuss: warn, or refuse, when `REPO_ROOT` isn't an ancestor of the cwd (or of `git rev-parse --show-toplevel`). Workaround until then: `unset VIRTUAL_ENV` and run from `engine/`, so `uv run` uses that worktree's own `.venv`.
