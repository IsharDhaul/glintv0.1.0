# WT-08 decisions

- 2026-10-29: `BuildManager` (in `api/build.py`) owns one read-only DuckDB connection per build. Each request gets its own `cursor()`, because DuckDB connections aren't safe to share across FastAPI's worker threads and cursors are. Data derived from a build (registry, sector counts, meta, search index) is cached on the `Build` object, so a swap drops all of it at once and nothing from one build is served under another's `build_id`.
- 2026-10-29: Pointer checks: while a build is being served, `current.json` is stat'ed at most every 30 s (`POINTER_CHECK_SECONDS`). The stat key is mtime_ns + inode + size, because the pipeline's atomic replace changes the inode. With **no** usable build, it is re-stat'ed on every request: a stat costs microseconds, and the first build then shows up at once instead of after up to 30 s. The old connection isn't closed explicitly, so in-flight requests on its cursors finish; it is released when the last reference goes.
- 2026-10-29: `/api/meta` returns **200** with a "No build yet" warning when `current.json` doesn't exist (WT-00 behaviour: the header still renders). Every build-backed route returns 503 `NO_BUILD` with the same message (`run glint fixtures synthetic or glint refresh`). An unreadable pointer, or a pointer to a missing file, is 503 `NO_BUILD` everywhere, meta included. `/api/health` is always 200. `/api/presets` doesn't need a build (presets are config) and returns 200 with `build_id` null.
- 2026-10-29: `build_id` on every response: JSON bodies carry it per the models. Every response, the CSV export included, also carries an `X-Glint-Build-Id` header, exposed to CORS.
- 2026-10-29: CORS allows exactly `^http://localhost:30\d\d$` (§8.5 web ports). `127.0.0.1` is not allowed: the brief says localhost only, and the web dev server is opened on localhost.
- 2026-10-29: `/api/sectors` lists **every** `Sector` in enum order with its count of `metrics_snapshot` rows (all kinds, before any universe filter), including zeros. That way the UI can show an empty sector instead of silently dropping it (principle 6).
- 2026-10-29: `/api/meta` now fills `last_run`, and `source_timestamps` from the latest `pipeline_runs` row (both empty on synthetic builds), and appends that run's warnings to `warnings`.
- 2026-10-29: `/api/screen` passes the engine's `ScreenResponse` through unchanged: no result cache. The engine is well under budget (see the performance entry), so a cache would only add a way to serve stale results. If one is added later, key it by `build_id` + the canonical Screen JSON. The body is the `Screen` object only. A whole preset posted by mistake gets a 422 `INVALID_SCREEN` whose message says to send `.preset.screen`.
- 2026-10-29: Export (§2.12): the rows are the screen's **results**, honouring `limit`, so the export matches what the table shows. The columns are `rank` (when ranked), `ticker` (if it's not already a column), then `columns` in order, then `as_of_fundamentals`, `as_of_prices` (per company, from the snapshot) and `notes` (`metric: CODE (message)`, `; `-joined). Null cells are **empty** and `notes` says why, so a missing value is never a 0 or a "—" string to parse around. Floats are written at full precision, as fractions. Filename: `glint-<slug of screen.name>-<export date>.csv`, where the export date is the server's local date (the data date is in the as-of columns).
- 2026-10-29: `/api/distribution` covers the **default universe** (`Universe()`, §2.3), or that universe restricted to one sector with `within=sector&sector=…`. A GET has no screen to take a universe from. It reuses WT-04's compiled universe query (`CompiledScreen.sql`), so the distribution can't drift from what a screen sees. `within=sector` needs `sector`, and `sector` without `within=sector` is a 422 (rather than being silently ignored). Unknown or not-live metrics are 404 `UNKNOWN_METRIC`, and yes/no metrics are a 422. Bins: 30 equal-width bins between p1 and p99, with the first bin starting at the minimum and the last ending at the maximum. That way fat tails (ROIC of −55 or +89 on synthetic data) don't squash the histogram into one bar, yet every value is counted. These are display parameters, not screening thresholds, so they live in code (`HISTOGRAM_BINS`, `HISTOGRAM_CLIP`).
- 2026-10-29: Search tiers are exact ticker → ticker prefix → name prefix → fuzzy name (rapidfuzz `WRatio` ≥ 70), up to 10 results with one hit per CIK. Tickers compare on letters and digits only, so `brk b`, `BRK-B` and `brk.b` all equal `BRK.B`, and the hit shows the class that matched. Within a tier, results are ordered by market cap descending (nulls last), then ticker. This matters because fuzzy scores tie a lot: "appel" scores 80 against Apple Inc., Apple Hospitality and Applied Materials alike, and size is the honest tie-breaker that uses data rather than a hand-made popularity list. Every company kind is searchable, and the hit carries `kind`. The index is cached per build. `FUZZY_CUTOFF` is a display tuning, not a screening threshold, so it lives in code.
- 2026-10-29: Synthetic search cases stand in for the brief's real ones: four extra companies are inserted into a test build. `orchad` → SYNOR (misspelt name, like "appel" → AAPL), `synh b` → SYNH.B (share class, like "brk b" → BRK.B) and `syngl` → SYNGL over SYNG (like "googl" → GOOGL). WT-09 repeats the real cases.
- 2026-10-29: lz-string: own port of `decompressFromEncodedURIComponent` (`api/lzstring.py`, about 90 lines) rather than a new dependency, since the PyPI port is unmaintained. It works on UTF-16 code units, so emoji survive. Tests check it against vectors from the JS library (`lz-string@1.5.0`, `tests/api/lz_vectors.json`, generated once with node outside the repo).
- 2026-10-29: `why_passed`: one outcome for the universe, then one per filter **leaf** (depth-first, with its `filter_path`). A group has no single value to show. Each leaf's `passed` is the engine's own `l<i>_ok` column: the screen is compiled by WT-04's compiler with `pct_rank_gte 0` sector probes appended, one per numeric metric, to read the sector percentile (ascending, over the screen's universe, null when the sector is too small). If the company is outside the screen's universe, only the failed universe outcome is returned, because percentiles and filters are evaluated over the universe. Decode, JSON, shape and registry errors are 422 `INVALID_SCREEN` with paths under `["screen", …]`.
- 2026-10-29: Company drawer: `metrics` holds every live metric in registry order, each with its `metric_notes` reason (none are invented). `history` holds every series `metric_history` keeps for the company, so which sparklines exist is the pipeline's choice, not a list in the API. Points are FY then TTM, oldest first. `sources`: see the 2026-10-30 entry below.
- 2026-10-29: `glint serve` binds to `127.0.0.1` (the API has no auth), on `GLINT_API_PORT` (`--port` overrides), with reload on by default (`--no-reload` turns it off). It passes uvicorn `log_config=None, access_log=False`, so the only request lines are Glint's structured ones (`event=request method path status ms build`). It removes its own row from `tests/test_cli.py`'s STUBS list, as earlier worktrees did.
- 2026-10-29: Contract tests validate real responses (200s and the 404/422/501/503 error bodies) against the **committed** `contracts/openapi.json`, using a small strict validator in `tests/api/openapi_check.py`. It covers exactly the keywords the file uses and fails on any unknown keyword. This avoids adding `jsonschema` as a dependency. A second test checks that `create_app().openapi()` equals the committed file, so `make contracts` has nothing to change. The regenerated contract differs from `main` only in route descriptions (from docstrings). No request or response model changed.
- 2026-10-29: **Performance (step 10)**, 6,000-row synthetic build, M-series Mac shared with other worktree sessions (load average 7–9). Through FastAPI's TestClient (validation + JSON + ASGI), 40 timed runs after one warm-up, 3 runs of `tests/api/test_perf.py`: `/api/screen` with WT-04's 10 filters (pct-rank, vs-median, between, an OR group, missing:pass), a 2-factor rank and near misses: **p50 59–72 ms, p95 79–116 ms** (budget 300). `/api/companies/{t}`: **p50 10–14 ms, p95 13–26 ms** (budget 150). `/api/companies/{t}?screen=` (why-passed, Quality compounders): **p50 40–44 ms, p95 49–80 ms**. Over real HTTP against `glint serve --no-reload` on :8008: screen **p50 61 ms, p95 82 ms**, company **p50 9 ms, p95 11 ms**. The tests assert the §5.10 budgets themselves (300 / 150 ms), not a tighter local number, so a loaded machine doesn't turn them red. Seen today: WT-04's own in-process 100 ms test failed at load average 20 (another session's job) and passed again once it settled.
- 2026-10-30 (review): A failed open is now retried every 30 s even if `current.json` hasn't changed. Before, a pointer that landed before its file, or a transient lock, stayed 503 until the pointer changed again. Any exception while opening (not only DuckDB and contract errors) becomes 503 `NO_BUILD` with the message, rather than a stuck 500. While there is no usable build, a pointer *change* is still noticed on the next request.
- 2026-10-30 (review): A rebuild **at the same path** (`glint fixtures synthetic` rewrites `builds/synthetic.duckdb`) closes the old connection before reopening. Otherwise DuckDB's per-process instance cache hands back the old, unlinked database (`test_rebuild_in_place_serves_the_new_file` fails without the close). Requests in flight on the old cursors may then error; that's acceptable for a dev-only rebuild, since pipeline builds get new ids and paths.
- 2026-10-30 (review): The `X-Glint-Build-Id` header and error bodies use the build the request actually used, stored on `request.state` by the `current_build` dependency. Otherwise the manager's last known id is used, *without* a re-check, so the async middleware never opens DuckDB and a swap that lands mid-request can't relabel the response.
- 2026-10-30 (review): Ticker lookup and search's exact tier prefer a stored ticker typed exactly (`BRKB` the listing over `BRK.B`) before falling back to the punctuation-insensitive match, which goes to the larger company.
- 2026-10-30 (review): Export: ranked screens always run with `rank_score` internally, so a null `rank` cell carries the reason in `notes` (`rank: MISSING_INPUT (…)`), even when `rank_score` isn't a column (principle 3). `notes` lists reasons only for exported columns.
- 2026-10-30 (review): `web/src/lib/api/types.ts` being in sync is checked by CI's `contracts` job (`make contracts` + `git diff --exit-code`). It isn't re-tested in pytest because that would need node.
- 2026-10-30 (review): The why-passed timing test asserts the **screen** budget (300 ms), not the drawer's 150 ms. It compiles and runs the whole screen for one company, and in one loaded full-suite run its p95 crossed 150 ms (p50 stayed around 45 ms). The plain `/api/companies/{t}` test keeps §5.10's 150 ms.

- 2026-10-30: `sources` is filled now that #13 has merged. It lists distinct `financials.source_accn` for the company, each with its latest `filed`, newest first. `form` is null, and `url` is `https://www.sec.gov/Archives/edgar/data/<cik without leading zeros>/<accn without dashes>/` (§2.9). Derived rows (no accession) aren't sources. An accession with no `filed` date can't be represented (`filed` is required), so it's left out **and logged** (`sources_without_filed_date`) rather than dropped quietly. Synthetic builds have no `financials`, so their `sources` is `[]`.

## Contract change: nullable `SourceFiling.form` (merged 2026-10-30 as #13)

**Problem.** `/api/companies/{ticker}` returns `sources: list[SourceFiling]`, and `SourceFiling.form: str` is required. No build table records a filing's form: `financials` has only `source_accn` and `filed`, and WT-03's normalizer doesn't keep one. Filling `form` in would mean inventing it, which breaks principle 3.

**Change (decided 2026-10-29: make it nullable; no DB change):**
- `engine/glint/contracts/api.py`, `class SourceFiling`: change it to `form: str | None = Field(description="Form type (10-K, 10-Q, …); null when the build doesn't record it")`.
- No `DB_SCHEMA_VERSION` bump (no table changes) and no `dsl_version` bump. Add a line to `docs/decisions/CONTRACTS.md`.
- Run `make contracts`: `contracts/openapi.json` and `web/src/lib/api/types.ts` change for `SourceFiling.form` only.

**Downstream.** Nothing constructs `SourceFiling` today. WT-08 passes `form=None` until a later change records forms. The web shows "—" for a null form.
