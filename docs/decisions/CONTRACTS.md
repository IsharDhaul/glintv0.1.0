# Contract changes

Every change to a contract (Screen DSL, API models, enums, DB DDL, stage interface) gets one dated line here,
made in its own `contract-<desc>` worktree and PR (see `docs/worktrees/README.md` §8.6).

- 2026-10-28: WT-00 — initial contracts: `DB_SCHEMA_VERSION = 1`, `dsl_version = 1`.
- 2026-10-29: `has_facts` (requested by WT-01) — `companies.has_facts` and `metrics_snapshot.has_facts` (BOOLEAN NOT NULL), `CompanyHeader.has_facts`, `Universe.include_no_facts=false` (§2.3: CIKs with no XBRL facts are excluded by default, toggleable). `DB_SCHEMA_VERSION` 1 → 2; rebuild synthetic with `make synthetic`.
- 2026-10-29: `Exchange.TXSE` (requested by WT-01): the Texas Stock Exchange is added to `Exchange` and to `DEFAULT_EXCHANGES`. Since October 2026, 9 SEC-listed companies (ET, SUN, SUNC, USAC, DDS, TCBI, IBOC, CECO, OBK) are listed only on TXSE, and more are moving. Without this they would silently drop out of the default universe. The change is additive: no shape change, so `DB_SCHEMA_VERSION` and `dsl_version` stay the same. Saved screens with an explicit `exchanges` list are unaffected.
- 2026-10-30: `SourceFiling.form` nullable (requested by WT-08): `form: str | None` (still required, so always present). No build table records a filing's form (`financials` keeps `source_accn` and `filed` only), so `/api/companies/{t}` `sources` would otherwise have to invent one. API-only: no `DB_SCHEMA_VERSION` or `dsl_version` bump. The web shows "—" for a null form.
- 2026-10-30: `NearMiss.note` (requested by WT-04): optional `note: CellNote | None`, so a near miss whose compared value is null says why (principle 3). The engine sets the metric's `metric_notes` reason (MISSING_INPUT if none is stored), SMALL_PEER_GROUP for a too-small sector percentile/median, or NEGATIVE_DENOMINATOR for a ratio vs-median with sector median ≤ 0; null when the value is present. Reuses `CellNote` and existing `NoteCode`s. API-only and additive: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-10-31: `MetricDefinition.tells_you` / `MetricDefinition.misleads` (for WT-10's metric dictionary): optional `str | None = None`, so `config/metrics.yaml` (`extra="forbid"`) can carry plain-language "what it tells you" and "when it misleads" text; `docs/metrics.md` appends them to the Definition cell only when present, and the API's `MetricDefinition` (and generated TS type) gains them as optional fields. No text is written here; WT-10 owns it. Additive, no DB or DSL shape change: no `DB_SCHEMA_VERSION` or `dsl_version` bump. `make docs` also picked up WT-06's earlier metrics.yaml wording/status changes that had not been regenerated.
- 2026-11-02: foreign-checkout guard (bug from WT-09's decisions): `core/settings.py` gains `check_checkout()`, run once per process from the `glint` root callback and from `get_settings()` (so `make dev-api`'s bare uvicorn is covered). It refuses unless the nearest folder at or above the cwd holding `.git` (a directory, or a worktree's `.git` file) *is* `REPO_ROOT`. "REPO_ROOT is an ancestor of cwd" alone isn't enough: worktrees live under main's `.claude/worktrees/`, so main is an ancestor of every worktree and the reported case would pass. Outside any git checkout it falls back to the ancestor test. Override: `GLINT_ALLOW_FOREIGN_CHECKOUT=1`. `make dev`, `make check`, CI and the launchd template all `cd` into `<repo>/engine` first, so none needs the override. No contract shape change: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-11-02: `FlagId.MARKET_CAP_IMPLAUSIBLE` (`"market_cap_implausible"`): a data-quality flag for companies whose market cap is below their recent average daily dollar volume, the ~84 "type D" names behind WT-10.md's 109 (serial reverse-splitters and heavy diluters whose filed share count lags the price). `config/thresholds.yaml` gets only the flag's `question`, because `test_thresholds_cover_every_flag` requires every `FlagId` to be keyed. The rule, its window and its threshold come in a separate flag-engine PR (`engine/glint/flags/`). Additive enum value, no shape change: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-11-03: `Kind.NO_COMMON_EQUITY` (`"no_common_equity"`), requested by the fix-universe-classes worktree (WT-01 paths): issuers whose every listed ticker is a debt or preferred security (TVA's TVE/TVC bonds, NRUC and Qwest notes, CHS preferreds), so there's no common stock to screen. It joins `Universe.exclude_kinds`'s default (now spac, fund, shell, no_common_equity), so these issuers are left out by default and counted as an exclusion, not dropped. No `DB_SCHEMA_VERSION` or `dsl_version` bump: `companies.kind` stays VARCHAR and the enum only grows, so every saved screen still parses. A screen that spells out the old three-kind list keeps that list (and would include these issuers, as its author chose); one that omits `exclude_kinds` gets the new default. No company has the kind until WT-01's rule lands in a follow-up PR. Web: `KIND_LABEL`s ("No listed common stock" badge, "no-common" chip), the `defaults.ts` mirror, and the methodology "left out by default" line.
- 2026-11-03: `companies.is_up_c BOOLEAN NOT NULL DEFAULT false` and `companies.up_c_evidence VARCHAR`, requested by the fix-universe-classes worktree. An Up-C (AVEX: Class A + voting-only Class B paired 1:1 with exchangeable LLC units) has economic shares = every cover-page common class, but its EPS and diluted count cover Class A only, so market cap from them is too low (AVEX 2.16×). WT-01 detects it from each filing's own XBRL (a class's share of the cover total within ±1pp of the tagged NCI ownership %, matched class ≥ 4% of the total, domestic filers); `up_c_evidence` names the filing, classes and NCI %, so the share count's definition travels with the build (principle 2). WT-03's `shares.py` uses the economic count; that value reaches financials through `companies.parquet`, so no table is added. `DB_SCHEMA_VERSION` 2 → 3 (a table's shape changed: old builds must be rebuilt, which the API already enforces). The DEFAULT keeps every existing producer (synthetic builds, test helpers) valid without listing the columns. API and web exposure (a badge on the company page) is a follow-up, not in this change.
- 2026-11-22: `companies.finance_lease_status VARCHAR` (`'stated'` / `'not_stated'`; NULL when the latest 10-K/10-Q tags no finance-lease liability) and `companies.finance_lease_evidence VARCHAR` (the filing and the balance-sheet line(s) it names), for the finance-lease rule (user decision, WT-06.md 2026-11-22). ASC 842 filers tag `FinanceLeaseLiability…StatementOfFinancialPositionExtensibleList`, naming the line that holds the lease; on 2026-11-21, of 881 listed domestic filers with a finance lease, 292 present it outside debt, 200 inside a debt line, ~398 don't say (WT-01.md). WT-01 fills both from its cover cache (#55) and keeps the per-component lines and accession as its own `companies.parquet` columns, as for `economic_shares`; WT-03 adds the lease to the debt component unless the named line is the tag it picked; WT-06 writes the ⓘ note from these columns ("finance lease not counted: the filing doesn't say where it's presented" for `not_stated`). `DB_SCHEMA_VERSION` 3 → 4 (a table's shape changed: old builds must be rebuilt, which the API enforces). Both nullable with no default, so producers that omit them (synthetic builds, test helpers) stay valid.
- 2026-11-22: `NoteCode.INPUT_EXCLUDES` (`"INPUT_EXCLUDES"`, shown as value + ⓘ, in `NON_NULL_NOTE_CODES`), for the finance-lease rule (user decision, WT-06.md 2026-11-22): a total_debt-based value (EV, net debt, D/E…) whose company tags a finance lease but whose filings never say which balance-sheet line holds it, so the lease isn't counted; the note says what and how much. Neither existing info code fits (DERIVED_INPUT says an input was built; ASSUMED_TAX_RATE is ROIC's). Additive enum value; `metric_notes.code` stays VARCHAR, so no `DB_SCHEMA_VERSION` or `dsl_version` bump. Web: label in `lib/notes.ts`, methodology row; SPEC §2.4 row. `quality/audit.py` now excludes `NON_NULL_NOTE_CODES` from null rates instead of its own list of two. No metric writes it until WT-06's PR.
- 2026-11-22: `FlagOut.severity` (requested by the UI upgrade, docs/glint-ui-upgrade.md Phase 3): a required `FlagSeverity` (`caution` | `info`) on every flag the API returns. `caution` is about the business (dilution, coverage, cash, goodwill, SBC, negative equity, late filing); `info` is about reading the data (stale or restated filing, changed fiscal year, a share count that lags the price). The value comes from `config/thresholds.yaml` (`flags.<id>.severity`, principle 8) at response time, so the `flags` table and builds are unchanged: no `DB_SCHEMA_VERSION` or `dsl_version` bump. The UI uses it to style flags (ochre rule for caution, quiet for info).
- 2026-11-22: `/api/snapshot/meta` (`SnapshotMeta`, `SnapshotRows`) and `/api/snapshot/values` (binary), requested by the UI upgrade (docs/interaction-architecture.md): the current build's live metric values as columns, so the browser can preview a screen while the user drags a threshold. The server stays authoritative: every settled screen still runs through `/api/screen`. The values body is `len(metrics)` blocks of `n` little-endian float64 (NaN = null, booleans 1/0), then the same number of uint8 blocks of reason codes (0 = none, k = `note_codes[k-1]`); note messages stay server-side. It reads `metrics_snapshot` and `metric_notes` as they are, with no new computation, and is built once per build in memory (real build: 7,992 × 71, 1.3 s, 2.0 MB gzipped). `?build=<build_id>` makes responses `immutable`; otherwise `no-cache`. API-only and additive: no `DB_SCHEMA_VERSION` or `dsl_version` bump. `SnapshotMeta.screen_config` carries `float_tolerance` and `small_peer_group_min` from `config/thresholds.yaml`, so the browser compares exactly as the engine does.
- 2026-11-23: `MetaResponse.universe_rules` (`UniverseRules`, required) with `stale_annual_report_months: int`, requested by the UI upgrade (PR #76): the stale-exclusion threshold, read from `config/thresholds.yaml` (`freshness.stale_annual_report_months`) through `metrics.params.load_params()`, the loader the metrics stage uses, so the UI never hard-codes "15 months" (principle 8). It's on `/api/meta`, next to `universe_counts.stale`, and is filled even with no build. `SnapshotMeta.screen_config` would be the natural home but isn't on `main` yet (it's in #76). `web/mocks/meta.json` regenerated with `make synthetic`. API-only and additive: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-11-23: `PresetSummary.kind` (`PresetKind`: `screen` | `red_flags`, required, no default), requested by the UI upgrade, which found red-flag presets by a "(red flags)" name suffix. Every `config/presets/*.json` sets it explicitly; `accruals-risk` and `dilution-watch` are `red_flags`. `test_red_flag_presets_say_so` keeps the kind, the name suffix and the "A risk screen, not a buy list." opening in step. It's on the summary, so `/api/presets` can group without fetching each preset. Web: the mock list handler passes `kind` through. API and preset files only: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-11-23: `Preset.misses: list[str] = []`, requested by the UI upgrade: one short plain-language line per known blind spot, moved out of `how_to_read` (the wording kept, lightly recast to stand alone; no new claims). 10 presets get entries. Sentences about how a filter treats missing or zero inputs (`accruals-risk`'s zero-net-income note, `qarp`'s small-sector note, `dividend-durability`'s short-history note) stay in `how_to_read`, because they describe the filters rather than what the screen can't see, so `accruals-risk` has no entries. Statements a test pins to `how_to_read` (Glint's stated differences from the source) stay there. Web: the gallery's "How to read it" lists them under "What it misses", so `main` doesn't lose the text before #76 lands. Additive: no `DB_SCHEMA_VERSION` or `dsl_version` bump.
- 2026-11-23: `Sort.then: list[SortKey] = []` (max 2; `SortKey` = `{by, dir}`, which `Sort` now extends), requested by the UI upgrade for shift-click secondary sorts. Rows sort by `by`, then each `then` key, then ticker ascending; nulls go last for every key; `rank_score` is allowed as any key (by rank position, desc = best first) and needs a rank block wherever it appears. Keys must be unique; each is registry-checked at `["sort", "then", i, "by"]`. Every saved screen still parses (a missing `then` is `[]`), so no `dsl_version` bump; no DB change. The engine sorts in `screen/engine.py` `_sort_rows` (stable sorts, last key first), and `compile.py` selects every sort key. `tests/api/openapi_check.py` learns `maxItems`. The web mock engine (`mocks/generate.ts`) still sorts by `by` only.
