# WT-04 decisions

- 2026-10-29: Most of step 1 already lives in the contract (`validate_against_registry`, pydantic shape rules for `between`, weights, depth, limit). `glint.screen.validate.check_screen` calls it, then adds two engine rules: rank factors must have a `better` direction (a `neutral` metric like `market_cap` has no "best" end), and each factor may appear only once. Synthetic liveness reuses the existing `load_registry(treat_all_as_live=True)` flag.
- 2026-10-29: A `frac`/`pp` threshold with `|value| > 2` is a **warning** (returned with the response), not an error, because a growth ≥ 300% screen is legal.
- 2026-10-29: User values reach DuckDB only as **named** parameters (`$p0`…), so fragments can be composed in any order. Identifiers pass an allow-list (snapshot fixed columns + registry ids) and a snake_case check before quoting. `tests/screen/test_injection.py` parses `compile.py` and fails on any f-string interpolation that isn't a `*_sql` fragment, a constant, an integer position or a safe helper call.
- 2026-10-29: One query per screen with four CTE layers (universe → window stats over the universe → leaf values → leaf/step booleans). The sieve, near misses, ranking and sorting run in Python over the ≤ universe-sized row set (no pyarrow needed). A second tiny query counts the snapshot, the universe and the universe if null bounds passed.
- 2026-10-29: Universe numeric bounds (`market_cap_min/max`, `avg_dollar_volume_min`, `max_days_since_filing`) exclude nulls: a company without a market cap isn't "≥ $1B". The universe step's `removed_missing` counts the rows only a null bound kept out.
- 2026-10-29: `removed_missing` = companies that the step removes but that **would pass if every null passed** (each leaf has an optimistic `opt` column). This is exact for nested AND/OR groups too, and is 0 for `missing: pass`.
- 2026-10-29: SMALL_PEER_GROUP uses the count of **non-null values** in the sector (within the universe), not the sector's company count: a percentile among 3 values is meaningless even if the sector has 50 members. The threshold comes from `thresholds.yaml` `metrics.small_peer_group_min`.
- 2026-10-29: Percentile = DuckDB `percent_rank()` partitioned by `(x IS NULL)` (plus sector), so nulls stay out of the window without a join-back. `pct_rank_*` filters use the raw ascending percentile ("top 30%" = `pct_rank_gte 0.7`). Ranking percentiles are direction-aware (best = 1).
- 2026-10-29: **vs-median**: for `frac`/`pp` the compared value is `x − median` (e.g. `0.02` = +2 pp); for other units it's `x / median`, null when the median ≤ 0 (a ratio to a non-positive median means nothing). Near misses report the raw value against the raw threshold the median implies (`median + v` or `median × v`).
- 2026-10-29: **Near-miss distance**: `|x − t| / |t|`. When `t = 0` it's the absolute gap `|x|`. For `between` it's measured to the nearer bound. For percentile filters it's the plain percentile gap `|pct − t|`, reported with the company's percentile as `value`. A failed OR group reports its closest child, and a failed AND subgroup its furthest failing child. Missing values and categorical tests have no distance and sort last.
- 2026-10-29: Ranking scores every universe row in the rank scope, so percentiles don't move when filters change (§2.5: stats after the universe, before other filters). Rank positions number the passing rows only. `percentile_composite` re-normalizes weights over the factors present, and its contributions sum to the score. `rank_sum` is Σ(wᵢ / mean w)·rankᵢ (equal weights give Greenblatt's plain sum), uses `rank()` with 1 = best, and **requires every factor**: summed ranks with a factor missing aren't comparable. When the score is null, the `rank_score` cell carries `SMALL_PEER_GROUP` if a missing factor came from a small sector, else `MISSING_INPUT`.
- 2026-10-29: For sorting, `rank_score` `desc` means **best first** for both methods: lowest sum for `rank_sum`, highest score for the composite. Unranked rows come last. Every sort puts nulls last and breaks ties by ticker ascending. The binding step is the filter step (not the universe) with the largest `removed`, first one on ties, and there is none if nothing was removed.
- 2026-10-29: Presets are checked at load time for shape, kebab-case id, known **P0** ids and engine rules, using a treat-all-live copy of the registry. Liveness is left to run time, because the real registry still marks every P0 as `planned` until WT-06 lands. The 3 starters use the §2.8 starting thresholds; Magic Formula is a ranking only, so it has no filters and no near misses.
- 2026-10-29: **Performance (step 11)**: p95 for 10 filters (pct-rank, vs-median, between, an OR group, missing:pass) plus a 2-factor rank and near misses on 6,000 synthetic rows, in-process on an M-series Mac under load from other sessions: **p50 52 ms, p95 56–80 ms** across 4 runs of `tests/screen/test_perf.py` (40 timed runs each, budget 100 ms). The first version fetched every universe row with ~55 columns: **p50 130 ms, p95 330 ms**, most of it DuckDB→Python conversion. Three changes got it under budget. (1) The universe CTE projects only the columns the screen touches, since window operators materialize every column. (2) The engine fetches only passing rows and near-miss candidates (rows failing exactly one step), with the funnel counts cross-joined from a one-row aggregate over a `MATERIALIZED` CTE, so the screen is evaluated once; windowed `count(*) FILTER … OVER ()` was tried and is ~5× slower. (3) Display columns are read for the result page only. The thresholds YAML is also parsed once (`@cache`). The full-evaluation `CompiledScreen.sql` stays for tests.
- 2026-10-29 (review): validation now also rejects `rank_score` in `columns` without a rank block (it would be a null with no reason, breaking P3), `rank_sum` with `within: sector` (ordinal ranks from sectors of different sizes aren't comparable: a 9-company sector can't rank worse than 9, which breaks P7), and `exchanges: []` (it would silently empty the universe).
- 2026-10-29 (review): `not_null` removals count as `removed_missing`, because the company would pass if the value were present. `is_null` removals don't, because those companies *have* data. A null `exchange` keeps a company out of the universe and is counted in the universe step's `removed_missing`.
- 2026-10-29 (review): `ResultRow.values` follows the order of `columns`, `rank_score` included.
- 2026-10-29 (review, open): when a sector percentile or median is null because of SMALL_PEER_GROUP, a near miss on that filter shows a null value and distance with no reason code, because `NearMiss` has no notes field. The funnel counts these companies as missing data. Only the `rank_score` cell carries the SMALL_PEER_GROUP note today. Fixing this needs a contract change (a `note: CellNote | None` on `NearMiss`), proposed for the §8.6 protocol rather than done here.
- 2026-10-29 (review): the perf test asserts p95 < 100 ms locally (the brief). On CI (`CI` env set) it asserts SPEC §5.10's 300 ms API budget instead, so a noisy shared runner can't turn `main` red. The local number is the one recorded above.

## Proposed contract change: a reason code on `NearMiss` (for a `CONTRACT:` worktree)

**Problem.** A near miss can fail because its compared value is null: the raw metric is null (MISSING_INPUT, n/m…), or a sector percentile or sector median is null because the sector has fewer than `metrics.small_peer_group_min` non-null values (SMALL_PEER_GROUP). `NearMiss` then shows `value: null`, `distance: null` and no reason, which breaks principle 3 (every null carries a reason code). Result rows don't have this problem, because `ResultRow.notes` carries reasons, but `NearMiss` has no equivalent field.

**Change (one schema, one field):**
- `engine/glint/contracts/api.py`, `class NearMiss`: add `note: CellNote | None = Field(default=None, description="Why value (or the percentile/median it is compared through) is null; null when value is present")`. It reuses the existing `CellNote {code: NoteCode, message: str}`, so no new enum values.
- Additive and optional, with a default. There is **no** `DB_SCHEMA_VERSION` bump (no table changes) and **no** `dsl_version` bump (the Screen DSL is unchanged). Add a line to `docs/decisions/CONTRACTS.md`.

**Regenerated by `make contracts`:**
- `contracts/openapi.json`: `NearMiss` gains `note` and stays out of `required`. CI's `contracts` job runs `git diff --exit-code contracts/ web/src/lib/api/types.ts`, so the regenerated files must be committed in the same PR.
- `web/src/lib/api/types.ts`: `NearMiss` gains `note?: components["schemas"]["CellNote"] | null`.
- `contracts/screen.schema.json`: unchanged, because it is the Screen request schema, not the response.

**What breaks downstream:**
- **Nothing at compile or test time.** The field is optional, and today only `glint/screen/engine.py` builds `NearMiss`. A keyword it doesn't pass falls back to `None`. No web code reads `NearMiss` yet: there are no references outside the generated types.
- **Engine (WT-04 path, a follow-up after the CONTRACT PR merges): fill the field.**
  - `compile.py`: add `sp_<metric>` to the narrow row columns for every leaf that compares through a sector stat (`pct_rank_*` with `within: sector`, `vs_sector_median_*`).
  - `engine.py`, `_near_misses`: when the explaining leaf's compared value is null, set `note` to SMALL_PEER_GROUP if `sp_<metric>` is true, else to the company's `metric_notes` row for that metric (fetched for near-miss CIKs only, like `_notes`). A ratio vs-median with median ≤ 0 has no note code today. Propose NEGATIVE_DENOMINATOR, since the median is the denominator.
  - Tests: a sector `pct_rank` near miss on the 60-row tiny build has `note.code == SMALL_PEER_GROUP`, and a null-ROIC near miss carries the `metric_notes` code.
- **Web (WT-05 / WT-09):**
  - Show `note` in the near-miss list, using the existing `NOTE_DISPLAY` mapping ("—" vs "n/m").
  - In mock mode, the MSW handlers that synthesize `ScreenResponse` may set or omit `note`; both are valid.
- **API (WT-08):** passes the engine's `ScreenResponse` through, so no change.
- **Optional, same PR, a judgement call:** `FunnelStep` could split `removed_missing` by reason (for example a `removed_small_peer: int`) so the funnel can say "cut because sectors are too small" rather than "missing data". It's not needed to fix principle 3, so leave it out unless the UI wants it.
- 2026-10-30: Timing tests (this file's step-11 test and WT-08's `tests/api/test_perf.py`) carry a `perf` marker. `make check`/`make test` skip them; CI runs them as their own step; `make perf` runs them locally. Under load from other sessions the local p95 measured the machine, not the engine, and failed in three sessions while CI passed. An untimed `test_ten_filters_shape` keeps the perf screen in `make check`. Retries and a looser local budget were rejected: both hide real slowdowns.
- 2026-10-30: Resolved by CONTRACT `NearMiss.note`. Sector-scoped leaves (sector pct-rank, vs-median) now carry `sp_<metric>` in the rows query; notes are looked up only for the ≤ 25 near misses shown whose compared value is null.
