# WT-05 decisions

- 2026-10-29: Fonts are Geist Sans + Geist Mono from the `geist` npm package (pinned 1.7.2, `next/font/local` under the hood) rather than `next/font/google`, which downloads at build time. CI and offline builds need no network.
- 2026-10-29: Palette adjusted from the SPEC §3.4 proposal so every text token meets 4.5:1 on bg/surface/surface-2 (checked by script):
  - dark `accent-2` lightened to `#5FB3B9`, because `#3C8D93` fails as link text;
  - light accent/pos/neg/warn darkened.
- 2026-10-29: `warn` moved from amber to orange (dark `#F08C3A`, light `#A24A00`) and `neg` from vermillion to pink-red (`#F2667A` / `#B3203C`). Amber `warn` was indistinguishable from gold `accent`, especially in light (`#7A5A0C` vs `#875800`). The mock banner keeps the spec's amber through its own fixed `banner` token, the same in both themes.
- 2026-10-29: Theme and density are `data-theme` / `data-density` attributes on `<html>`, set by an inline `<head>` script from localStorage before first paint (Next 16 "preventing flash" guide). The first visit follows `prefers-color-scheme`.
- 2026-10-29: Sieve trays scale their inner bar by √(remaining / universe), not linearly, so a 58-company final step is still visible next to 4,812.
- 2026-10-29: Hidden tooltips are `display: none`, not `visibility: hidden`. Invisible tooltips near the right edge still widened the page at 390 px. `aria-describedby` still resolves hidden content.
- 2026-10-29: `format.ts` starts in step 1 with `formatCount` only, so the sieve and histogram never format numbers themselves. The kitchen sink's other sample values are literal strings until step 3.
- 2026-10-29: Kitchen-sink page (/dev/kitchen-sink, commit be19ac0) signed off by the user, including the orange `warn`, the √-scaled sieve bars and the Geist fonts.
- 2026-10-29: Data layer = `openapi-fetch` over the generated `paths` + TanStack Query hooks (`src/lib/api/hooks.ts`). One `ApiError` with `kind: network | no_build | http` drives the API-down / no-build / error states. Retries are off for network/no_build (a retry won't fix them).
- 2026-10-29: `config.ts` defaults now spell out `process.env.NEXT_PUBLIC_GLINT_*` literally. Next only inlines that literal form, so the WT-00 `env = process.env` default made the browser bundle think mock mode was off (requests leaked to :8000, hydration mismatch).
- 2026-10-29: MSW loads browser-only through `next/dynamic(..., { ssr: false })`, because `msw/browser` has no server build. It renders nothing and never wraps children, which avoids a hydration mismatch. In mock mode the API client's `fetch` awaits `mockReady`, so no request can leave before the worker controls the page. `start()` is memoised (Strict Mode double effects).
- 2026-10-29: Mock scenarios via `?mock=down|nobuild|empty|slow|ok` (sticky per tab in sessionStorage) so the UI states can be exercised and e2e-tested on purpose.
- 2026-10-29: Mock responses are seeded by the request JSON (deterministic). Every ScreenResponse carries the warning "Synthetic mock response: rows are sampled, not filtered." Near misses use the row's own synthetic value with `distance: null`, rather than fabricating a value that would look like correct filtering.
- 2026-10-29: Mock presets live in `src/mocks/presets.ts` (3 from SPEC §2.8) until config/presets/*.json exists (WT-04/WT-10). The real ones arrive through /api/presets in WT-09.
- 2026-10-29: Contract gaps found (not changed; to propose via §8.6):
  - (1) `/api/distribution` has no threshold → `pass_count`, so the "N companies pass" counter under the input can't be exact without counting in the browser.
  - (2) `/api/distribution` takes no universe, so the histogram can't reflect the *current* universe as §3.3 asks.
  - (3) The history series in §2.9 (FCF, share count) have no registry ids; the mock uses `fcf_margin` and `share_count_change_yoy`.
  - (4) `score` metrics carry no maximum, so "7/9" needs a scale (e.g. `scale_max` on MetricDefinition).
- 2026-10-29: Number formats (format.ts):
  - usd keeps 3 significant digits above $1K ($1.24B, $312M, $1.00M) and rounds before picking the suffix, so it never prints "$1000M";
  - frac/x use 1 dp, pp is always signed, days are whole;
  - negatives use the typographic minus (−) and never show "−0.0".
  - Dates use a fixed locale and time zone (UTC calendar dates; the fundamentals timestamp in America/New_York, as "… 03:00 ET") so server and browser render identical text.
- 2026-10-29: units.ts parses what users type in display units ("15", "15%", "+2 pp", "−4.2", "1,250", and for usd "300M" / "$1.5B"). It converts ×100 for frac/pp exactly once and strips float noise (0.07 × 100 → 7). `inputText` always round-trips through `parseInput`.
- 2026-10-29: Enforcement is a Vitest grep test (`no-stray-formatting.test.ts`) that fails on toFixed/toPrecision/toLocale*/Intl.NumberFormat/Intl.DateTimeFormat anywhere but format.ts. It's simpler than a custom lint rule and covers .tsx too. Kitchen-sink samples are now storage-unit values rendered through format.ts, not literal strings.
- 2026-10-29: `MetricValue` is the one cell renderer: null → NullValue with reason, info notes → ⓘ, `pp` changes → ▲/▼ + pos/neg. The piotroski_f "n/9" scale is a display constant in format.ts until the contract carries a scale (gap 4).
- 2026-10-29: User confirmed: usd always shows 3 significant figures with trailing zeros kept ($1.00M, not $1M).

The default sort is rank_score desc when ranked, else ticker asc.

- 2026-10-29: Filter builder:

Categorical filtering is offered for `sector` only (in / is / is not); ticker/name/exchange/kind filters exist in the DSL but aren't useful as builder filters.

- 2026-10-29: DSL notes from the UI (not changing them; for §8.6 if wanted):

- 2026-10-30: Two history bugs found by e2e and fixed:
